# 拼音搜索设计（全拼）

- 日期：2026-11-15
- 状态：已确认，已出实现计划，待实现
- 范围：engine 查询层（新增 `pinyin` 模块 + `query` 集成）；索引格式、扫描、增量、持久化、daemon、protocol、client、GUI 均无改动
- 功能代号：pinyin-search

## 1. 背景

中文用户习惯不打输入法、直接敲全拼搜文件。macOS 自带的 Spotlight / Finder 支持这个行为：索引时给中文 token 存罗马字读音标注，查询时以拼音匹配标注。代价在 Spotlight 自己的磁盘索引里，不占应用内存。

本项目自建常驻内存索引（24B/条，daemon 基线 41MB），不复用 Spotlight。要在不增加索引内存的前提下拿到同等体验，选择**查询侧展开**：把拼音词切分成语节，展开成「读音以该音节开头的汉字集合」，直接在文件名里做字符序列匹配。

## 2. 目标与非目标

### 目标

1. 纯字母全拼查询命中中文文件名：`shu` → 数/书/树/熟…；`shuxue` → 数学；`shux`（未打完）→ 数学。
2. 索引、内存布局、落盘格式零改动，旧索引直接可用，无迁移。
3. GUI 与 CLI 经 daemon 自动获益，protocol 不变。
4. 逐键查询（GUI 60ms 防抖）下结果连续，打字过程中不闪烁。

### 非目标

- **首字母匹配**（`sx` → 数学）。歧义集合过大，查询侧展开不可行；将来如需要，走索引侧预存拼音序列（Spotlight 式），本设计的匹配器边界为它预留。
- 索引侧拼音预存。
- 混合词（`数xue`）、通配符词（`shu*`）、`whole:` 词的拼音展开。
- 日文假名、韩文等非汉字表音文字的读音匹配。
- 配置开关：默认开启，不提供关闭项。

## 3. 行为契约

### 3.1 启用条件

一个 `Name` 词同时满足以下条件才编译拼音分支，其余一切维持现有字面匹配：

1. 整轮非 `case:`（`case:` 是精确意图，拼音是模糊召回，不叠加）且非 `whole:`。
2. 词只含 ASCII 字母与 `'`（小写折叠后判定；大写字母不影响展开——`Shu` 与 `shu` 同）。数字、空格、其他符号出现即不展开。
3. 词能切分为合法音节序列（见 3.2），否则静默回退为纯字面。
4. 不是 `path:` 词（路径词恒不展开）。

### 3.2 切分

- 音节表：由读音数据派生（ASCII 完整读音约 419 个，含 `hm`/`hng`/`m`/`n` 等叹词音节；`ü` 记作 `v`）。派生而非硬编码的目的是保证切分表与字符集同源：表里没有的音节必然也匹配不到任何字。
- 完整音节优先。枚举**全部**可行切分（每段为完整音节，末段可为任意音节前缀），全部参与命中（OR）。歧义切分是真实需求：`fangan` 同时应命中方案（fang+an）与反感（fan+gan）；`xian` 同时命中先（xian）与西安（xi+an）。
- `'` 为强制分段边界：边界两侧各自单独切分，边界内仍全枚举。`xi'an` 至少产出 `[xi][an]`，另有 `[xi][a][n]`（`a`、`n` 都是完整音节）。
- 可行切分超过 8 种时截断取前 8 种（按最长优先顺序），防御组合爆炸。
- 无任何可行切分（如 `pdf`、`shuxq`）→ 不展开。

示例：

| 查询词 | 切分 |
|---|---|
| `shu` | `[shu]` |
| `shuxue` | `[shu][xue]`、`[shu][xu][e]` 等 |
| `shux` | `[shu][x]`（末段前缀） |
| `sh` | `[sh]`（末段前缀） |
| `fangan` | `[fang][an]`、`[fan][gan]`、`[fa][n][gan]` 等（上限 8 种） |
| `xi'an` | `[xi][an]`、`[xi][a][n]` 等 |
| `pdf` | 无可行切分 → 不展开 |
| `dot` | 无可行切分（`do` 非完整音节、`dot` 非任何读音前缀）→ 不展开 |

### 3.3 读音与字符集

- 音调剥离；`ü` 归一为 `v`（`lv` → 绿/律，主流 IME 习惯）。
- 多音字任一读音参与：`数`（shǔ/shù）在 `shu` 集；`长`（cháng/zhǎng）同时在 `chang` 与 `zhang` 集；`行`（xíng/háng）同时在 `xing` 与 `hang` 集。
- 字符集按「读音前缀」建，完整音节段与其他段共用同一规则：前缀 `sh` 的集 = 任一读音以 `sh` 开头的全部汉字；完整音节 `shu` 的集 = 任一读音以 `shu` 开头的全部汉字，因此 `shu` 既命中 数/书/树，也命中 水（shui）/双（shuang）/说（shuo）。这是 IME 候选式的召回语义（输入 `shu` 的候选含水/双/说），列为已知局限而非缺陷。
- 字符域：CJK 统一表意文字基本区 U+4E00–U+9FFF。扩展区与兼容区汉字不直接参与；注意名称在匹配前经 NFC 归一，可归一到基本区的兼容汉字（如 U+F900）会以归一后字符参与（边缘情形）。

### 3.4 命中语义

- 拼音命中 = 文件名中存在**连续**汉字序列，逐字归属对应音节的字符集（第 i 字 ∈ 第 i 段集）。字符集之间不允许插入其他字符。
- 命中位置任意：`shu` 命中「报告书」。
- 命中选择：对一个词，字面匹配 OR 拼音匹配任一成立即命中；多个切分方案任一成立即命中。
- 拼音分支只看文件名（`match_name`/display 名），与字面匹配同数据源；CJK 字节不受小写折叠影响。

### 3.5 评分

现有相关度档位（3 = 名称开头命中，2 = 字面整词边界，1 = 子串）：

- 拼音命中起点在名称首字节（首字符）→ 档 3。
- 拼音命中起点在名称中部 → 档 1。
- 字面与拼音同时命中取高档位。字面的整词边界档（2）只来自字面匹配。

效果：`shu` 下「数学.pdf」（拼音开头）排在「季度报告书.docx」（拼音中部）之前。

### 3.6 与现有语法的交互

| 查询 | 拼音展开 |
|---|---|
| `shu` | ✓ |
| `shuxue` | ✓ |
| `shux` | ✓（末段前缀） |
| `xi'an` | ✓（强制分段边界） |
| `Shu` | ✓（折叠后纯字母） |
| `case:shu` / `case:README` | ✗（整轮） |
| `whole:shu` | ✗ |
| `shu*.pdf` / `*shu` | ✗（含通配符） |
| `path:shu` | ✗ |
| `数xue`（混合词） | ✗（词含非字母） |
| `dot` | ✗（`do` 非完整音节、`dot` 非读音前缀，切分失败） |
| `pdf` | ✗（无可行切分） |

### 3.7 默认行为

无开关，默认开启。关闭方式不存在（`case:`/`whole:` 可作为单次查询的规避手段）。

## 4. 架构

### 4.1 模块划分

新增 `crates/engine/src/pinyin.rs`，对 `query.rs` 暴露 `PinyinMatcher`（其余条目为模块内部）：

```
pinyin.rs（全部逻辑内聚，query.rs 只做接入）
├── readings(c) -> Vec<String>   单字归一化读音（去声调、ü→v、去重）
├── ReverseTable       音节前缀 → 字符集 + 完整音节集；OnceLock 全局懒构建
├── segment(word)      全部可行切分（上限 8），每方案是音节子串序列
├── CharBitmap         CJK 基本区位图，2.6KB/音节集
└── PinyinMatcher
    ├── compile(word: &[u8]) -> Option<Self>
    │                 词级条件 + 切分 + 位图展开；None = 不展开（静默回退字面）
    └── hit(name: &[u8]) -> Option<usize>
                      序列匹配，返回命中起点字节位（全 ASCII 名短路）
```

- 反查表在 daemon 进程内首次出现可展开查询词时构建（`OnceLock`），毫秒级，常驻 ~500KB。
- 位图每次查询按需从反查表切片构建（每音节微秒级，一次查询总构造成本可忽略）。

### 4.2 query.rs 集成点

1. `CPattern` 增加字段 `pinyin: Option<PinyinMatcher>`（`query.rs:470`）。
2. `CPattern::compile` 增加入参 `pinyin_ok: bool`（整轮开关判定，`query.rs:476`），词级条件为：无通配符（`Pattern` 新增 `wildcard` 字段——`*shu*` 编译后 `parts` 与纯字面词完全一致，必须由解析侧标注，不能只看 `parts`）、字节 ⊆ `a-z'` 且至少一个字母。
3. 词命中点（`query.rs:268`）改为：

   ```
   CPattern::hit(target) = match_pattern(target, self)
                        || self.pinyin.as_ref().is_some_and(|m| m.hit(target).is_some())
   ```

4. 评分（`query.rs:592`）：`score_of` 对首词额外取拼音命中起点；起点为 0 → 3，否则 1，与字面档取 max。
5. `whole:` 边界判定（`query.rs:271`）不改：整轮 `whole:` 下拼音分支不存在。
6. `path:` 词（`query.rs:162`）以 `pinyin_ok = false` 编译。

唯一编译入口在 `execute`（`query.rs:161-162`）；`execute_sorted` 委托 `execute`，无需改动。

### 4.3 匹配算法

```
PinyinMatcher::hit(name):
  若 name 全 ASCII → None（快速路径）
  逐字符起点 s 扫描:
    对每个切分方案（按顺序，首个命中即返回）:
      从 s 起逐字符推进: 该字 ∈ 方案第 i 段位图 ?
      任一段失败 → 试下一起点
      全部段完成 → Some(s)
```

CJK 字符按 UTF-8 首字节长度步进（复用 `utf8_char_len` 语义）；非 CJK 字符不在任何位图中，序列自然中断。

### 4.4 数据源

engine 新增依赖 `pinyin`（rust-pinyin）：纯数据静态表，多音字读数由上游维护，无 IO、无网络。

风险预案：若上游多读音 API 无法支撑反查表构建，降级为仓库内生成表——从 Unihan 数据离线生成、checkin 二进制，项目已有 vendor 先例。实现计划第一步先验证 crate API。

## 5. 性能预算

- 编译期：切分 + 位图构建，单查询词微秒级，`execute` 一次。
- 匹配期：
  - 全 ASCII 文件名：`is_ascii` 短路，零开销。
  - 含中文名：位图 membership 测试。1M 条目、CJK 名占比 20%、平均 15 字符、2 音节 ≈ 600 万次位测试，rayon 并行下增量 <1ms。
  - 最坏（全 CJK、6 音节）估算并行 <10ms；以基准实测为准。
- 内存：索引内存布局零改动；查询侧反查表懒构建、常驻 ~500KB（仅拼音查询触发）；查询期位图瞬态常规 ≤100KB，极端（8 方案 × 6 音节）理论上限 ~125KB。
- 落盘：零变化。

验收口径：`scripts/bench.sh` 增加拼音查询基准项，1M 条目含中文名场景，增量在预算内方可通过。

## 6. 错误处理与降级

全部静默降级，无用户可见错误路径：

| 情形 | 行为 |
|---|---|
| 切分失败 | 纯字面匹配 |
| `case:` / `whole:` / 通配符 / 含数字符号 / `path:` / 混合词 | 不展开 |
| 文件名含非汉字字符 | 天然不命中，不误伤 |
| 反查表构建 | 纯内存计算，无 IO 无失败面 |

## 8. 已知局限

1. 首字母不支持（`sx` 不命中数学）。设计边界为其预留：将来到索引侧方案时，`CPattern` 的拼音分支换成索引序列匹配，行为契约不变。
2. `xian` 同时匹配先与西安（全切分 OR）；`xi'an` 只强制该处边界，边界内仍子切分（仍可能按 `[xi][a][n]` 命中三字序列），不保证只命中两字词。
3. 混合词（`数xue`）不展开；`whole:` 与通配符词不展开。
4. 单字母查询（`s`）集合达数千字，结果噪音大；逐键输入时短暂出现，属可接受行为。
5. 仅 CJK 基本区汉字直接参与；经 NFC 归一后落入基本区的兼容汉字可能参与（边缘）。
6. `ü` 只接受 `v` 写法（`lv` → 绿），不接受 `lü`（与主流 IME 一致）。
7. 完整音节段使用前缀集，召回偏宽：`shu` 也命中 水/双/说，`shuxue` 可命中「水学」「双学」类组合（IME 候选式语义）。
