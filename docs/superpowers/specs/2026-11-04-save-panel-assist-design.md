# 保存面板目录助手设计

- 日期：2026-11-04
- 状态：已确认，进入实现计划
- 范围：app 新增第三视口浮层 + 保存面板检测 + 跳转执行；engine/protocol/client 仅加目录过滤参数
- 功能代号：save-panel-assist

## 1. 背景

在任意应用保存文档时，系统弹出保存对话框，用户难以在目录树中定位目标目录。期望：输入目录名即时搜索，选中后保存面板自动跳转到该目录，直接点保存。

技术边界：保存面板（NSSavePanel）属于宿主应用，macOS 10.10+ 由系统面板服务进程（openAndSavePanelService）渲染。无公开 API 向其中添加 UI 或直接设置目录；无 scripting 字典、无 IPC 入口；私有 API 在 Developer ID 公证分发下不可用。

可行链路：全局搜索目录（引擎已有 `FLAG_DIR`）→ 浮层展示 → 向前台应用合成 ⌘⇧G 打开「前往文件夹」→ 写入完整路径 → 确认跳转。同类实现：Alfred 路径跳转、Default Folder X。

前置判断：本功能需要辅助功能（Accessibility）权限；本项目经 Developer ID 签名 + 公证分发（非 Mac App Store），无沙盒限制，发合成事件可行。悬浮条已是 NonactivatingPanel（不激活宿主），浮层沿用同一组合。

## 2. 目标与非目标

### 目标

1. 检测到前台应用弹出保存/打开面板时，自动在面板附近浮出目录搜索框。
2. 输入即时查询引擎（仅目录），↑↓ 导航，回车或双击选中后保存面板自动跳转到目标目录。
3. 跳转期间保留用户剪贴板内容（save/restore）。
4. 设置项默认开启；依赖辅助功能权限，未授权时不产生任何干扰，授权后自动生效。
5. 检测、判定、跳转各环节均有降级出口，失败不影响面板正常使用。

### 非目标

- 向保存面板内嵌任何 UI（无公开 API，不可行）。
- 直接代用户点击「保存」或修改文件名。
- 兼容自绘保存 UI 的应用（网页版文档、部分 Electron 自定义面板）：此类面板无法跳转，走错误降级出口。
- 手动兜底热键、最近使用目录排序、排除列表（二期候选）。
- 非前台应用的面板监听。

## 3. 总体方案

```
NSWorkspace(前台切换) → panel_detector → overlay(浮层窗口) → query(daemon 查目录)
                              ↓                              ↓
                      dialog_navigator ←←←←←←←←←←←← 选中目录结果
                      (⌘⇧G + AX直设/剪贴板粘贴 + 确认)
```

### 3.1 检测机制：前台应用单 AXObserver

保存面板只能由前台应用弹出（模态）。因此同一时刻只需一个 AXObserver：NSWorkspace 监听前台应用切换（`didActivateApplicationNotification`），切换时把 observer 换绑到新前台应用 pid，监听窗口创建与焦点窗口变化通知。

- observer 回调绑定固定 runloop 线程处理，不做跨线程销毁（与 FSEvents 流线程纪律同类）
- AX 权限拒绝时静默降级：功能不启用，不影响其他功能

两级判定保存面板：

1. 快速信号：window subrole（`AXSystemDialog` / `AXDialog` 等）
2. 确认信号：子元素结构特征（可编辑文件名输入框 + 按钮组）

特征表独立为数据结构（可序列化、可修订，应对 macOS 版本漂移）；判定函数设计为纯函数（输入特征快照 → bool）。

### 3.2 触发范围与默认值

- 打开/保存面板都触发：跳转目录对两者同样有用，且判定无需解析本地化按钮文案。
- 功能默认开启（`save_panel_assist` 默认 `true`），意图是开箱即用。辅助功能权限无法随安装授予：未授权时检测层静默不生效，不以任何形式干扰面板；设置页该项显示「需授权」状态与跳转系统设置的按钮；启动时检测到「开关开启且未授权」则提示一次（托盘菜单入口，不重复打扰），授权后自动生效。

### 3.3 浮层窗口（第三视口）

- 独立 NSPanel，复用悬浮条五要素 NonactivatingPanel 组合（canBecomeKeyWindow / NonactivatingPanel / Floating / CanJoinAllSpaces / orderFrontRegardless），集中在 `platform/mac.rs` 同层
- **改类后窗口销毁前必须还原窗口类**（winit drop abort 教训，沿用现有纪律）
- 位置：紧贴保存面板下沿（浮层顶 = 面板底,间隙 0,水平居中对齐面板;越界两轴独立钳制进所在屏安全区），定位算法为纯几何函数。（2026-11-05 修订:原「优先右侧 → 越界下方」实机观感不佳,改为下沿贴合优先）
- 高度自适应（2026-11-05 二次修订）：面板下方可用空间不足期望高度 300 时压缩到可用值（下限 140 = 搜索行 50 + 页脚 30 + 至少一行结果 44 + 余量 16,可滚动）,返回实际高度、调用方须按返回尺寸设窗;面板底贴近屏幕底的退化场景浮层取下限并贴屏幕安全区下缘,最多叠入面板下部约 132pt（下限随 2026-11-06 尺寸改版重校;评审接受此取舍,Esc 关浮层后按钮可见）
- 出现即成为 key window 接收键盘，宿主 app 不被激活；操作完成或 Esc 后立即让出 key
- 视觉定版（2026-11-06 实机迭代）：宽 600；不透明纯色底（无毛玻璃，内存优先）；色板 `tokens::overlay` 深浅两套（整表钉住测试）；页脚键帽组（↑↓ 选择 / ⏎ 跳转 / esc 关闭；**空态也恒显**——与原型「空态仅 esc」不同，实机定版）；**结果区全出血无横向内边距**（原型 8px 内边距作废，实机定版）；文件夹 glyph 为自绘矢量两段式（后标签 = 前身同色系加深，实现派生色；取代 v1 原型「NSWorkspace 系统真实图标」路线，内存优先）；深浅主题跟随——唤起即补查 + 浮层 pass 节流探测（与悬浮条/设置窗同纪律）
- 长路径显示（2026-11-06）：路径行先家目录压缩 `/Users/<name>` → `~`；仍超宽才中段省略（头锚点 + … + 尾部，二分对齐可用宽，确定性）；悬停行 tooltip 回全路径；数据层零改动，复制/跳转永远全路径
- 输入框提示：「输入文字搜索，选择目录回车后自动跳转」（中英两套；空态引导文案仍为「输入目录名…」）

### 3.4 跳转执行（dialog_navigator）

⌘⇧G 是唯一不可省的合成键（打开「前往文件夹」无 AX 等价入口）。后续动作双策略：

```
策略 A（优先）：⌘⇧G → AX 定位路径输入框 → AXUIElementSetAttributeValue(kAXValue) 直设路径（读回校验）
              → 合成 Return 统一提交（与策略 B 同构；「前往」按钮 AXPress 保留为 M0 探针验证点⑥的对照实验）
策略 B（降级）：⌘⇧G → 剪贴板暂存原内容+写入路径 → 合成 ⌘V → 合成 Return → NSPasteboard API 写回原内容
```

- 策略 A 失败当场降级 B，并记录成功次数；实机数据决定 A 是否默认启用。macOS 升级打断 A 时 B 兜底
- **每步合成前 AX 状态确认**：发 ⌘V / Return 前确认输入框仍在 AX 树中；用户中途按 Esc 关闭「前往文件夹」sheet 时中止整个序列。防竞态：若无此确认，后续合成的 ⌘V 会粘进文件名框、Return 触发意外保存
- 「固定延迟一次投递」（连发键序列赌延迟）与「逐层操作面板侧栏导航」两个替代方案不取：前者比 AX 确认更脆，后者深层路径慢且脆

### 3.5 查询侧

- `protocol::Request` 查询消息加 `dir_only: bool`
- 引擎查询后按 `Entry::is_dir()`（`FLAG_DIR`）过滤
- 浮层搜索走现有 client → Unix socket → daemon 链路；daemon 离线则检测层不触发浮层（功能依赖引擎，不出残缺体验）

## 4. 交互流

```
检测到保存面板 → 浮层出现在面板旁，成为 key window，输入框聚焦
  → 输入实时查 daemon（dir_only）→ 目录列表（目录名 + 完整路径）
  → ↑↓ 导航，回车或双击选中
  → 浮层 orderOut（先隐藏，保证按键不被浮层截获）
  → navigator 执行跳转（策略 A，失败当场降级 B）
  → 面板定位到目标目录，焦点回到文件名框，用户点保存
```

- Esc：隐藏浮层，不跳转。浮层是 key window 时键事件只路由给浮层，不穿透面板；用户取消保存需第二次 Esc（此时面板已是 key，走原生取消）
- 不打扰规则：Esc 关闭浮层后，浮层隐藏且在本次面板存续期间不再自动重现；面板关闭后不保留任何记忆，下次打开同一面板时浮层照常出现
- 面板关闭时浮层同步隐藏（浮层非 key 场景下用户直接 Esc 取消保存，浮层靠 AX 通知收尾）

## 5. 错误处理

| 情形 | 处理 |
|---|---|
| 辅助功能权限未授予 | 设置开启时引导授权（`AXIsProcessTrusted` → 跳系统设置）；未授权时功能静默不生效 |
| 前台 app 隐藏 AX 树 | 换绑失败静默跳过该 app |
| 判定误报 | 浮层不拦截鼠标，面板仍可正常操作；Esc 关闭；特征表数据化可修订 |
| navigator 策略 A 失败 | 当场降级 B |
| 策略 B 也失败（超时） | 浮层不隐藏，显示「路径已复制，请手动 ⌘⇧G 粘贴」错误态——路径已在剪贴板，错误出口仍是可用出口 |
| 用户中途按 Esc 关闭「前往文件夹」 | 每步合成前 AX 状态确认，检测到输入框消失即中止序列 |
| daemon 离线 | 检测层不触发浮层 |
| 面板在浮层使用中关闭 | AX 通知 → 浮层隐藏 |
| 剪贴板写回失败 | 不影响主流程，原内容延后可见 |

## 9. 2026-11-06 实机修订（跳转后状态与启动时序）

### 9.1 跳转成功后浮层重现、输入被清空

- 现象：跳转链路成功，但目录切换完成后浮层重新出现，搜索框为空。
- 根因：⌘⇧G 的「前往文件夹」子 sheet 会让保存面板暂时从 `AXWindows` 消失；
  扫描因此判 `NoPanel` 并发出 `Closed`，接线层清掉 `handled_pids`。子 sheet 关闭
  后保存面板重新可见，又被当成新面板发 `Shown`，`overlay.open()` 复位输入。
- 修复：扫描三态增加「存在其他 sheet」判据——候选窗口里只要有不通过面板判定
  的 `AXSheet`，且当前处于本助手跳转窗口内（`mark_navigating` 置 2s 截止），
  返回 `Unknown` 而不是 `NoPanel`（`transient_sheet_blocks_close`）。宿主的
  无关 sheet 不会长期压制 `Closed`；子 sheet 消失后 observer 的销毁通知会再次
  扫描，届时无 sheet 才可确认关闭。
- 钉住测试：`transient_sheet_only_during_navigation`（突变改成只看
  `saw_sheet` 必红）。

### 9.2 回车后节奏「按步骤走」

实机日志（`MCE_APP_LOG`，全局 `+xxms` 时间戳）显示 1289ms 的构成：

| 阶段 | 耗时 | 性质 |
|---|---|---|
| 回车 → ROOT 取走请求 | 104ms | eframe 对不可见窗口的 100ms 重绘节流 |
| 基线采集（同步 AX 树遍历） | 83ms | 可消除 |
| 发 ⌘⇧G → 定位输入框 | 386ms | 系统 sheet 动画 |
| AX 直设路径 + 读回 | 3ms | 可忽略 |
| Return → 目录切换完成 | 816ms | 系统导航（随目标路径/文件系统变化） |

两项修复：

1. **基线预采集**：浮层唤起时后台线程采集可写输入框基线（`panel_baseline`），
   回车后由跳转线程直接消费；pid 不匹配/为空时同步采集兜底。
2. **主队列投递**：浮层 pass 内只取走请求与状态，`orderOut` + 启动跳转经
   `dispatch2::DispatchQueue::main().exec_async` 投到主队列，等当前 pass 结束后执行。不可在本 pass
   内同步 `orderOut`——实机证明宿主保存面板来不及拿回键盘焦点，⌘⇧G 落空，
   跳转直接失效。

修复后同链路实测 1013ms；可控部分（187ms）归零，剩余为系统 sheet 动画与目录
导航。ROOT 消费路径保留为兜底（浮层 pass 未跑时）。

### 9.3 跳转完成后保留浮层与搜索状态（2026-11-06 产品修订）

原设计「提交后 orderOut，本面板存续内不再自动出现」在实机反馈中不符合使用
预期：用户跳转后仍希望看到搜索浮层，且输入内容不能被清空。

修订后的行为：

- 提交跳转：`OverlayState::hide_keep_state` 只隐藏窗口，不清输入/结果/选中，
  保留 `panel_pid`；
- 跳转成功（`NavigateOutcome::Done`）：接线层校验五门（助手启用、浮层未显示、
  结果 pid 仍归因当前面板、定位 frame 仍在、未被 Esc 屏蔽）后调用
  `platform::overlay_show_passive` 被动复现——定位 + `orderFrontRegardless`，
  **不 makeKey**，键盘焦点留在宿主保存面板，用户可继续输入文件名/保存；
  输入/结果/选中原样保留；
  - 为什么不让浮层持有焦点：makeKey 复现会抢走保存面板的键盘焦点，用户无法
    继续输入文件名（2026-11-06 实机反馈）。
  - 二次跳转：点击非 key 浮层会让 macEverything 自身成为前台。navigator 在
    发 ⌘⇧G 前检测到「前台不是宿主」时，先激活宿主 app，再用 AX `AXRaise` +
    `AXFocused` + `app.AXFocusedWindow` 恢复保存面板焦点，以
    `AXFocusedWindow == 保存面板` 读回确认后才发键（实机确认
    `focused_window_is_panel=true`，跳转成功）。
- 失败/中止（FellBack/Aborted）：维持原行为（FellBack 显示「路径已复制」，
  Aborted 不复现）；
- 保存面板关闭（`Closed`）：浮层照常关闭并清空状态；
- Esc：仍按 `close` 清空并屏蔽本面板。

由此替代原不打扰规则中的「跳转成功后静置不再出现」一项（验证清单 2.6）；
「Esc 关闭后本面板不再自动弹」不变。

### 9.4 运行期开关与授权即时生效（2026-11-06 实机反馈）

现象：用户在系统设置授权后切回 App，功能不生效，必须重启。

- 根因：授权跃迁只在 ROOT 的 `logic` 帧检测；设置页可见但 ROOT 没有重绘
  请求时（用户直接去系统设置授权再切回），跃迁永远不被发现。
- 修复：
  - 授权跃迁收敛到 `refresh_panel_assist_trust_shared`，ROOT `logic` 与设置页
    pass 共用；设置页可见期也能发现 false→true 并置一次性 detector 启动标记；
  - 启动时若「开关开启但未授权」，静默挂授权监视器（500ms 轮询，5 分钟上限），
    授权后主动唤醒 ROOT 消费启动标记；
  - 设置页开关关→开仍走 `apply_panel_assist` → pending → ROOT logic 启动
    detector，无需重启。
