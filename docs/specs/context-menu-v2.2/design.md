# 右键菜单 v2.2 设计：移除「在访达中打开」

- 日期：2026-10-18
- 状态：已实现（v2.3 合并落地，2026-10-19）
- 关联：`docs/specs/v2-ui/product.md` §2、`docs/specs/i18n-v2.1/plan.md` Step 4

## 1. 背景与目标

现有结果窗口右键菜单为四项：打开 / 在访达中打开 / 在访达中显示 / 拷贝路径。

- **「在访达中打开」冗余**：它只打开所在目录、不选中目标；「在访达中显示」已覆盖绝大多数使用意图
  （搜索到文件后要操作它）。目录项本来就不显示它（与「打开」语义重复）。
- 产品决定删除该项，菜单收敛为三项。文件与目录从此共用同一套菜单。

同时评估过「在访达中打开系统菜单…」（调用 Finder 自己的完整右键菜单）。技术上可行且已完成实机
PoC，但产品决定**不做**，理由见 §2。该结论记录在此，避免后续重复调研。

## 2. 决策：不采用 AX 系统菜单

- macOS 没有公开 API 让第三方 App 弹出 Finder 的原生右键菜单；唯一可行路径是 Accessibility（AX）：
  在 Finder 中定位元素并执行 `AXShowMenu`。
- 2026-10-18 在本机（macOS 26）实机验证通过：列表/图标/分栏/画廊四视图均可用、多选可用、
  后台线程调用不阻塞主线程；`AXShowMenu` 会以 `-25204` 超时返回但菜单已正常弹出。
- **不做的原因**：
  - 需要「辅助功能」强权限，用户接受度低；ad-hoc 签名重建后授权可能失效；
  - 依赖 Finder 的 AX 内部结构，系统升级可能回归；
  - 每次 0.5–2s 延迟，且会把 Finder 切到前台、菜单出现在另一个 App 中，体验割裂；
  - 跨目录多选无法使用；
  - 收益仅是相对「在访达中显示 + 用户自己右键」**省一次右键**，对搜索工具不值。
- 若未来确有系统动作需求，优先做无权限、稳定的「打开方式」子菜单（LaunchServices 枚举）。

## 3. 范围

**包含**

- 删除 `MenuAction::OpenInFinderDir` 及菜单项、执行分支、测试。
- 菜单不再依赖文件/目录计数：删除 `count_types`，`menu_items` 简化为无参。
- 同步产品/使用文档与 i18n 计划（删除该文案与相关分支）。
- 单测与实机回归。

**不包含**

- AX 系统菜单（已否决，见 §2）。
- 「打开方式 / 共享 / 服务」等自建菜单。
- 修复「在访达中显示」逐项 `open -R` 的既有批量选中问题（独立跟进）。
- 本次不实现右键菜单的 i18n（仍属 i18n v2.1 Step 4 的未完成工作，见 §6.4）。

## 4. 菜单结构

删除后，文件与目录的菜单**不再有类型差异**，混选亦然：

| 菜单项 | 行为 |
|---|---|
| 打开 | 文件 = 默认应用打开；目录 = 访达进入 |
| 在访达中显示 | 在父目录中选中该项 |
| 拷贝路径 | 复制完整路径（多选逐行） |

- 多选逐项执行；「拷贝路径」逐行复制。
- 菜单仅在选中 ≥1 行时弹出（既有约束不变）。
- NSMenu tag 重新编号（纯进程内标识，无持久化）：

| 动作 | tag |
|---|---|
| 打开 `Open` | 1 |
| 在访达中显示 `RevealInFinder` | 2 |
| 拷贝路径 `CopyPaths` | 3 |

## 5. 交互与错误处理

交互不变：右键行 → 标准表格语义收敛选中 → 弹出原生 NSMenu → 执行所选动作。

错误处理不变：先做整批存在性校验，任一缺失则整批不执行并落状态栏
「文件不存在，索引可能待更新」；执行失败不静默。

## 7. 验收

**单测**

- 文件 / 目录 / 混选的菜单项均为「打开 / 在访达中显示 / 拷贝路径」。
- tag 往返（1–3；0/未知不映射）。
- 三个动作的命令面与现状一致；缺失路径在 spawn 前失败；空集不发无参 `open`。

**实机**

- 单选文件、单选目录、多选（含文件+目录混选）右键均只出现三项。
- 打开（文件默认应用 / 目录访达进入）、在访达中显示、拷贝路径均正常。
- 陈旧索引路径 → 状态栏报文件不存在。
- 中英文构建下菜单项数量与行为一致（文案本地化仍按 Step 4 的进度，不在本次范围）。

## 9. 决策记录

1. **删除「在访达中打开」**：不选中目标的「打开所在目录」在搜索场景价值低，且与「在访达中显示」重叠；
   目录项原本就不显示它。
2. **不做 AX 系统菜单**：技术可行，但权限、脆弱性、延迟与体验割裂的成本远高于「省一次右键」的收益。
   结论与 PoC 证据保留在 §2，后续不再重复调研。
