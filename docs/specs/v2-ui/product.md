# macEverything v2.0 图形界面 产品规格

**Status:** 写作中
**version:** 1.0.0
**updated:** 2026-10-16
**产品依据:** v1-core/product.md(v1 引擎已验收);本 spec 定义 v2.0 双形态图形界面

---

## 概述

v1 交付了引擎与命令行(v1 非目标清单:悬浮条/完整窗口/设置/菜单栏/i18n,即本版范围)。v2.0 给引擎装上**双形态图形界面**:悬浮条(⌥Space 唤起、快进快出)+ 完整结果窗口(Everything 主窗式、浏览与批量),两者共享同一常驻引擎;菜单栏常驻、开机自启、引擎不在自动拉起。v2.1 再补设置页与 i18n。

### 需求要点

- 悬浮条:全局快捷键唤起、输入即搜、键盘全操、打开后自动隐藏、多屏跟随
- 完整结果窗口: Everything 主窗模式——多列(名称/大小/时间/路径)、点列头排序、多选批量、右键菜单、状态栏
- 菜单栏常驻:左键唤起搜索、右键菜单、引擎状态可见
- 开机自启:默认开启,重启系统后 App 与引擎自动就位
- 引擎缺失自动拉起:App 启动检测,不在则自动启动
- 引擎扩展:按列排序查询(完整窗口需要;v2.0 唯一引擎改动)

## 问题

1. v1 只有命令行,日常找文件的「唤起-输入-打开」链路需要开终端敲命令,距「Everything 级手感」有落差。证据:v1 使用记录——查询本身 2-3ms,但**交互链路**远超查询成本。
2. 不常驻:每次使用要手动 `macEverything start`(或先启动终端),引擎的秒开/增量优势被交互成本抵消。
3. 结果只能看文本列表:无排序/多选/批量,浏览大量命中时能力不足。

## 目标

每条可度量,v2.0 验收逐条复测。

1. 唤起响应 < 100ms(按下 ⌥Space 到悬浮条可见)。
2. 输入到结果渲染 < 150ms(含输入防抖;引擎查询本身 2-4ms)。
3. App 常驻内存 < 100MB;悬浮条隐藏时 App CPU 0%(`top` 实测)。
4. 引擎不在时自动拉起,≤ 3s 内可搜(含首扫期间的部分结果可用性)。
5. 重启系统后(自启开启)无需任何手动操作,悬浮条唤起即可搜。
6. 完整窗口:约 120 万条目(2026-10-16 实测 1,197,010)下搜索响应与悬浮条同级;四列排序切换正确;多选(shift/⌘/⌘A)与批量右键操作实测正确。
7. 悬浮条在全屏应用上方可见(以 PoC-1 通过为前提,见「待决策」)。

## 交付形态

- **交付物 = `macEverything.app`**(GUI 应用包):菜单栏常驻(`LSUIElement=true`,无 Dock 图标)与 `SMAppService` 开机自启都要求 bundle 形态。
- **CLI 二进制随包**:`macEverything`(引擎+命令行)置于 `Contents/MacOS/macEverything`(或 `Contents/Resources/`),与 App 同版本同批打包——App 拉起引擎**优先按包内相对路径定位**,包外 PATH 仅作开发场景兜底;随包优先同时消除版本漂移(同包同版,协议 v 字段可拒混跑)。
- **安装位置**:`~/Applications/macEverything.app` 或 `/Applications`(用户自选;自启注册用当前实际路径)。
- **组装方式**:`scripts/bundle.sh` 手工组装(cp 二进制 + 生成 Info.plist + 可选图标),不引入打包框架依赖;版本号与 workspace 一致。
- **CLI 与 App 的关系**:同一二进制项目的两种入口(GUI 入口与命令行入口分属不同 crate 产物),互不依赖运行;装了 App 不强制装 PATH,反之亦然。

### 引擎定位顺序(App 拉起引擎时)

1. `current_exe()` 同目录 / `Contents/MacOS/` 下的 `macEverything`(随包路径,首选)
2. PATH 查找(开发场景)
3. 均未找到 → 悬浮条内显示可操作错误,**并列实际搜索过的全部路径**

## 功能描述

### 1. 悬浮条

**行为描述**:

- 按下 ⌥Space(全局快捷键)→ 悬浮条出现在**鼠标当前所在屏**,水平居中、垂直偏上(Spotlight 式位置);无边框、圆角阴影、置顶。
- 再按 ⌥Space 或 Esc 或失焦 → 隐藏;重复唤起居中位置重置、输入框清空(每次唤起都是全新查询)。
- 输入即搜(防抖 60ms):连引擎实时查询;引擎不在则先自动拉起,拉起期间输入框角标显示「启动引擎中」。
- 结果行:文件名 + 所在目录(灰色小字);「共 N 项」计数;索引状态角标(文案映射见 §7)。
- 分页语义:**首查一次取满 1000 条**(协议上限),UI 初始渲染前 20 行,滚到底部时本地增量渲染后续行(不重查、不翻页请求)。

**键位**:

| 键 | 行为 |
|---|---|
| ↑ / ↓ | 移动选择 |
| ↵ | 用默认应用打开文件;**打开后悬浮条自动隐藏** |
| ⌘↵ | 在 Finder 中显示 |
| ⌥↵ | 打开完整结果窗口并带入当前查询词 |
| Esc | 隐藏 |
| (失焦) | 隐藏 |

**分流规则**:选中项为目录时,↵ = 在 Finder 中打开该目录。

### 2. 完整结果窗口

**行为描述**:

- 入口:托盘菜单「打开完整窗口」;悬浮条 ⌥↵(带当前查询词);全局快捷键 ⌃⌥Space 直达(空词打开;与悬浮条备选位 ⌥⇧Space 互不占用)。
- 窗口常规 App 行为:可缩放、可最小化;关闭窗口不退出 App(托盘常驻)。
- 顶部搜索框(与悬浮条同一引擎与语法);输入即搜(防抖 60ms)。
- 结果表格列:**名称 / 大小 / 修改时间 / 路径**;
  - 点列头切换排序(升/降序,再次点击反向);默认排序 = 匹配质量(v1 引擎口径)。
  - 列宽可拖拽调整;窗口内滚动虚拟化(只渲染可见行)。
  - 大小/修改时间由引擎响应携带(daemon 端并行读取,非逐行异步补齐);按大小/时间列排序时读取耗时随响应返回,状态栏可见;排序中的等待以状态栏「排序中…」提示,结果到达整体替换(不做行级占位闪烁)。
- 多选:单击选中;shift 范围选;⌘ 点选切换;⌘A 全选。
- 右键菜单:**原生 macOS 菜单**(系统观感,非应用自绘);**菜单项按选中类型收敛**(目录不出现重复语义项):

| 菜单项 | 文件 | 目录 | 多选 |
|---|---|---|---|
| 打开 | 默认应用打开 | 在访达中打开(进入) | 逐项打开 |
| 在访达中打开 | 打开所在目录 | (目录的「打开」即此语义,不重复出现) | 逐项 |
| 在访达中显示 | 父目录中选中该项 | 父目录中选中该项 | 逐项选中 |
| 拷贝路径 | 复制完整路径 | 同 | 逐行复制全部路径 |

  混选(文件+目录)时按「两者语义的并集」呈现(打开/在访达中打开/在访达中显示/拷贝路径 四项齐全)。
- 底部状态栏:`N 项 · 匹配 X ms · 读取 Y ms · 索引状态`。**「N 项」= 命中总数(total)**,响应条目可能因体积预算少于 total(超出时状态栏注明「展示前 1000 条」);`读取 Y ms` 仅在响应携带该计时时显示(按大小/时间排序)。
- **索引状态与缺口出口**:状态栏常驻显示索引状态;存在权限缺口或 IO 错误时显示可点击的「⚠ N 个目录未收录」徽标,点击展开缺口清单(目录 + 原因)——与 CLI `status` 消费同一状态源(§7 映射表)。
- 双击行 = 默认应用打开。

### 3. 菜单栏(托盘)

**行为描述**:

- 图标常驻菜单栏;左键单击 = 唤起/隐藏悬浮条(切换语义)。
- 右键(或长按):菜单「打开搜索」「打开完整窗口」「开机自启(勾选)」「退出」。
- 引擎状态在菜单中可见:首项按 §7 映射表显示六种状态之一;「未运行」时点击可启动;存在权限缺口时追加「⚠ N 个目录未收录」项(点击打开完整窗口并展开缺口清单)。

### 4. 开机自启

- 首次启动 App 时注册自启(默认开启);托盘菜单「开机自启」可取消/恢复。
- 自启对象 = App;App 启动时负责检测并拉起引擎(见 §5)。
- 取消自启时注销系统注册(不留残余)。

### 5. 进程编排(App 与引擎)

- App 单实例:数据目录内 App 自持小 socket(`app.sock`,与 daemon.sock 并列);重复启动时连接该 socket 发「唤起悬浮条」消息后自行退出——兑现「重复启动唤起已有实例」的承诺。socket 不可连(App 已退出但锁陈旧)则清理后正常启动。
- 启动时检测引擎(socket 连通性):不在则自动 spawn 引擎(定位顺序见「交付形态」节),角标显示启动进度。
- App 退出 ≠ 停引擎:引擎继续常驻(CLI 与下次启动仍可用);「退出」菜单只退 App。
- 引擎缺失且拉不起来时:悬浮条内显示可操作错误,**并列实际搜索过的全部路径**(见「交付形态」节定位顺序)。

### 6. 外观

- 悬浮条与完整窗口**跟随系统深浅色**即时切换(系统外观变化时重绘主题,无需重启)。

### 7. 索引状态呈现(与 v1 状态契约同一状态源)

v1 状态契约四态(building/ready/reconciling/degraded)+ 未运行 + 离线,在 GUI 全量映射,不得只接一半:

| v1 状态 | 悬浮条角标 | 完整窗口状态栏 | 托盘菜单首项 |
|---|---|---|---|
| building(首扫中) | 建索引中 N | 索引构建中(N 条) | 引擎:构建中 |
| ready | (无角标) | 就绪 | 引擎:就绪 |
| reconciling(停机重放) | 补齐中 | 索引补齐中(结果可能不全) | 引擎:补齐中 |
| degraded(全盘重扫) | 重建中 | 索引重建中(结果可能不全) | 引擎:重建中 |
| offline(daemon 不在,离线索引) | 离线索引 | 离线索引 · 生成于 … | 引擎:未运行 |
| 未运行(Daemon 未启动) | 启动引擎中 / 引擎缺失 | 同上 + 缺口出口 | 引擎:未运行 |

权限缺口(gaps)与 IO 错误计数:完整窗口状态栏徽标 + 托盘菜单项(§2/§3),与 CLI `status` 同源。

### 6. 引擎扩展:按列排序查询

- 完整窗口点列头时,查询按对应列排序(名称/大小/修改时间/路径;默认=匹配质量)。
- 排序对象 = 命中集全量;取前 N(与 limit 契约一致)。
- 悬浮条不使用此能力(保持质量排序)。

## 接口设计

单机应用,接口为 App ↔ daemon 的本机 socket 契约(v1 已存在,本版扩展):

**查询请求扩展**:在 v1 查询契约基础上增加排序字段。

| 字段 | 类型 | 说明 |
|---|---|---|
| query | 字符串 | 同 v1(语法不变) |
| limit | 整数 | 同 v1(≤1000) |
| sort | 字符串,可选 | `relevance`(默认)/`name`/`size`/`mtime`/`path`;缺省 = relevance(v1 客户端不受影响) |

**响应扩展**:结果条目保持 v1 字段(名称/路径/大小/修改时间);`total` 与 `elapsed_ms` 语义不变。

**自启与快捷键**:系统级注册(LaunchServices 自启 / 全局快捷键),无本机 socket 契约。

## 场景推演

**场景 1:日常即搜即开**
假设:引擎运行中,用户想找昨天写的一份报告。
- ⌥Space → 悬浮条出现(<100ms)→ 输入「报告」→ 结果 <150ms 呈现 → ↑↓ 选中 → ↵ → 文件用默认应用打开,悬浮条已隐藏

**场景 2:冷开机**
假设:重启系统,自启已开启,引擎未跑。
- 登录后 App 自动启动 → 检测引擎不在 → 自动拉起 → 引擎读落盘索引秒开 → 用户 ⌥Space 唤起即搜(全程无手动操作)

**场景 3:完整窗口浏览与批量**
假设:某关键词命中 800 项,用户要从结果里挑若干拷路径。
- 悬浮条 ⌥↵ → 完整窗口带词打开 → 点「修改时间」列头排序 → shift 选中连续区间 + ⌘ 点选补几项 → 右键「拷贝路径」→ 全部路径逐行进剪贴板

**场景 4:引擎崩溃/未安装 CLI**
假设:daemon 异常退出,或 CLI 不在 PATH。
- 唤起悬浮条 → 自动拉起(异常退出场景)→ 角标「启动引擎中」→ 数秒后可用;若 CLI 缺失 → 悬浮条内显示「未找到 macEverything 引擎(检查安装)」,可操作

**场景 5:全屏应用中使用**
假设:用户在浏览器全屏看电影/演示。
- ⌥Space → 悬浮条出现在全屏应用上方(跨 Space/浮动级别生效,PoC-1 通过为前提)→ 搜索/打开 → Esc 隐藏回归全屏

## 边界情况

| 异常 | 行为 |
|---|---|
| ⌥Space 被其他 App/输入法占用 | 启动时注册失败 → 弹提示,提供备选位(⌥⇧Space 等)供选择试用 |
| 跨 Space 行为不生效(PoC-1 失败) | 降级:唤起出现在当前 Space;文档如实标注局限 |
| 引擎构建中查询 | 悬浮条/完整窗口均可用,结果随构建推进增多;角标显示「建索引中」 |
| 查询无结果 | 显示「无匹配项」空态 |
| 打开的文件已被删除 | 打开失败提示(「文件不存在,索引可能待更新」) |
| 完整窗口结果过期(文件已删) | 懒 stat 读取失败的行显示「—」;右键打开报错同上 |
| 多屏拔插 | 每次唤起按鼠标当前屏定位;屏消失时退回主屏 |
| App 崩溃 | 引擎不受影响(独立进程);重启 App 恢复界面 |

## 验收标准

**功能**

- [ ] ⌥Space 唤起/隐藏;重复唤起居中位置重置、输入清空
- [ ] 悬浮条全键位(↑↓/↵/⌘↵/⌥↵/Esc/失焦)逐项实测
- [ ] ↵ 打开文件后悬浮条自动隐藏;⌘↵ Finder 显示正确
- [ ] 完整窗口:四列显示、点列头排序(升/降)、列宽拖拽
- [ ] 右键菜单为**原生 macOS 菜单**(与 Finder 一致的系统观感),四项语义(打开/在访达中打开/在访达中显示/拷贝路径)逐项实测
- [ ] 多选(shift/⌘/⌘A)+ 右键批量(拷贝路径/在访达中显示)实测正确
- [ ] 托盘:左键唤起/隐藏切换;右键菜单;引擎状态六态映射如实(§7 表)
- [ ] 状态呈现:补齐中/重建中在悬浮条与完整窗口可见;权限缺口徽标可点击展开清单
- [ ] 自启:重启系统后无手动操作可搜(真实重启验证一次)
- [ ] 引擎定位:随包路径优先命中;路径全失败时错误文案列出实际搜过的全部路径
- [ ] 引擎缺失自动拉起 ≤ 3s
- [ ] 完整窗口 ⌃⌥Space 直达;App 重复启动唤起已有实例悬浮条(app.sock 通道)
- [ ] 深浅色:切换系统外观后两窗口即时跟随

**性能**

- [ ] 唤起响应 < 100ms
- [ ] 输入到结果 < 150ms(约 120 万条目真实索引,2026-10-16 实测口径)
- [ ] App 常驻内存 < 100MB(top 实测)
- [ ] 悬浮条隐藏时 App CPU 0%(top 实测)

**体验**

- [ ] 全屏应用上方可见(PoC-1 通过时);不出现闪烁/残影
- [ ] 多屏:悬浮条出现在鼠标所在屏
- [ ] 完整窗口大结果集(1000 行)滚动流畅(虚拟化生效)

## 测试与验证

- **纯逻辑 TDD(engine)**:`execute_sorted` 四列排序正确性/截断边界/与默认排序共存;协议 `sort` 字段兼容(缺省=relevance,旧请求不受影响)。
- **纯逻辑(客户端侧)**:查询会话的防抖与响应代际号(丢弃过期响应);排序状态机(点击列头切换升/降/默认)。
- **v1 回归**:全仓 91 项(engine lib 77 + parity 2 + cli 12)全绿;CLI 冒烟(protocol/client 迁移后 start/query/status/stop/离线全链路)。
- **实机验收**(egui 渲染不做自动化,与 v1 同策略):
  - 双形态全链路(场景 1/3/4/5 逐条复现)
  - 多屏、全屏应用、深浅色跟随
