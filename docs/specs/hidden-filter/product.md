# 隐藏项搜索过滤（hidden-filter）产品规格

- 日期：2026-11-08
- 状态：待实现

## 1. 背景与目标

当前索引收录所有未被排除列表剪枝的条目，搜索结果中会混入 `.git`、`.config`、`.DS_Store` 等
名称以 `.` 开头的隐藏项。多数用户只想看「正常」文件，高级用户偶尔需要搜 `.ssh`、`.zshrc`。

目标：提供一个全局开关，控制搜索结果是否包含隐藏项；切换即时生效，不重建索引。

## 2. 语义

- **隐藏项**：名称以 `.` 开头的文件或文件夹（Unix 隐藏）。不采用访达的 `chflags hidden` /
  `.hidden` 清单语义。
- **过滤范围**：条目自身或**任一祖先目录**名称以 `.` 开头，即视为隐藏。例：
  - `.zshrc` → 隐藏；
  - `.config/nvim/init.lua` → 隐藏（祖先 `.config`）；
  - `Documents/.gitkeep` → 隐藏（自身）。
- **扫描根**：根条目不参与隐藏判定。用户显式索引的根（即使路径含 `.` 组件）不因本特性被隐藏。
- 过滤发生在**查询层**：索引内容不变，开关切换立即影响后续查询（含在途重查），无需重扫。
- 过滤同时作用于文件名词与 `path:` 词：被隐藏的条目不会以任何方式进入结果，也不计入 `total`。

## 3. 默认值与升级迁移

| 场景 | 默认行为 |
|---|---|
| 新安装（数据目录尚无落盘索引） | **不包含**隐藏项 |
| 升级用户（数据目录已有落盘索引，配置缺该字段） | 首次启动**设置为包含**，并写回 `config.toml` |
| 用户显式设置过 | 永远以用户值为准 |

迁移信号 = `index.bin`（落盘索引）是否存在。配置字段缺失且索引存在 → 视为升级用户，写入
`include_hidden = true`；配置字段缺失且索引不存在 → 视为新装，写入 `include_hidden = false`。
写回失败只记日志，内存仍按迁移结果生效。

## 4. 交互

### 4.1 设置页

- 位置：设置 → **索引**页顶部，新增「搜索」分组。
- 行：开关「包含隐藏项」，下方常驻说明「名称以 . 开头的文件和文件夹。关闭后不进入搜索结果。」
- 打开设置页时向引擎读取当前值；开关切换写入引擎配置并落盘。
- 切换成功（或引擎已临时生效但落盘失败）后，悬浮条与完整窗口按**当前查询词立即重查**，
  无需用户重新输入。
- 旧引擎：由既有 `engine_launcher::ensure_engine` 的版本偏差机制处理——App 启动时比对
  `Status.daemon_version`，不一致即 stop → 拉起随包 CLI（升级后开设置前引擎已被换新）。
  本特性不新增重启逻辑；若仍碰到不兼容引擎（如手动以相同版本号拉起旧二进制），
  行内展示错误并提示重启引擎。

### 4.2 搜索行为

- 悬浮条、完整结果窗口、保存面板目录助手（`dir_only` 查询）统一遵循全局开关。
- 隐藏过滤不改变排序、置顶（`.app`）与分页逻辑；`total` 为过滤后的命中数。

### 4.3 命令行

- `macEverything query` 默认遵循全局配置。
- 新增 `--include-hidden`：本次查询强制包含隐藏项（不修改全局配置）。
- `--json` 输出口径与在线/离线查询一致。

## 5. 非目标

- 不改变索引收录范围（隐藏项继续入索引）。
- 不支持按条目临时切换（无搜索框旁快捷开关）。
- 不实现 `chflags hidden`、`.hidden` 清单、访达「不可见」属性。
- 不新增搜索语法（如 `hidden:` 词）。

## 6. 验收标准

1. 新装环境默认搜不到 `.foo`、`.config/x`；开启开关后立即可搜到，无需重扫。
2. 升级环境（旧配置 + 已有索引）首次启动仍能搜到隐藏项，配置文件出现 `include_hidden = true`。
3. 关闭开关后，`.config/nvim/init.lua` 与 `.zshrc` 均不出现在结果中，`total` 同步减少。
4. 扫描根本身不以点开头时行为如常；根路径含点目录时不因本特性整体消失。
5. 悬浮条、完整窗口、保存面板助手、CLI（含 `--include-hidden`）、离线降级查询行为一致。
6. `exclude reset` 不重置该开关。
7. 三门禁（fmt / clippy / test）全绿；新增测试经突变验证。
