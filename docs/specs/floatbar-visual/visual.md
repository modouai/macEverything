## 零、范围界定

### 本规格交付什么

| 形态 | 面板尺寸 | 深浅两套 |
|---|---|---|
| 悬浮条 | 最大宽 700 / 窄屏自适应 × 内容高；窗口另加形象条 70 | 是 |
| 完整结果窗口 | 1080 × 627 | 是 |

### 本规格不交付什么

四张设计稿都画在 1280×800 的「桌面」上，其中下列元素是**背景语境，不属产品界面**：

| 设计稿元素 | 说明 |
|---|---|
| 壁纸渐变 + 四团光斑 | 用于衬托面板与窗口；产品中两形态都直接浮在用户真实桌面上 |
| 菜单栏（Apple 图标、访达、状态图标、时钟） | 属 macOS 系统，产品不绘制 |
| Dock（仅悬浮条屏有） | 属 macOS 系统，产品不绘制 |
| 交通灯（完整窗口屏） | 系统窗口装饰；egui 无边框窗口下是否自绘待定，见 §六.2 |

**毛玻璃的观感目标因此有条件**：产品里面板下方是用户的任意桌面内容，不是设计稿里可控的壁纸。见 §六.1。

#### 打开完整窗口按钮

悬浮条里**唯一可用鼠标点的入口**。完整窗口此前只有 `⌥↵` 一条键盘路径（`product.md` §1），页脚那组「完整窗口 ⌥↵」是提示、不是按钮——不知道快捷键的用户就找不到完整窗口。

| 属性 | 值 |
|---|---|
| 尺寸 | 28×28，圆角 7 |
| 图标 | `maximize-2` 18×18，比搜索图标亮一档（深 `#E8EAED` / 浅 `#1F242B`） |
| 静止态 | 底色深 `#FFFFFF1F` / 浅 `#0000000F` |
| 悬停态 | 底色加深（深 `#FFFFFF2E` / 浅 `#0000001A`） |
| 按下态 | 底色再深一档 |
| 提示 | 悬停显示 tooltip「在完整窗口中打开（⌥↵）」 |
| 点击 | 等同 `⌥↵`——打开完整窗口并带入当前查询词 |

**静止态必须一眼看得见。** 入口做「几乎透明」的静止态等于没有入口——用户找不到功能，就是设计失败。图标也要比装饰性图标（搜索图标）亮一档：它是要被点的，不该同一个灰度。

按钮与 §2.6 的状态角标同处搜索行右端：角标只在非 ready 状态出现，落在按钮左侧，两者不冲突。

| 属性 | 值 |
|---|---|

| 圆角 | 8 |
| 左右内边距 | 12 |
| 子元素间距 | 12，垂直居中 |
| 文件图标 | 32×32，**裸放，无块底**（见下「文件图标走系统真实图标」） |

**宽度分配**（行宽 684 = 最大宽下；窄屏 = panel_w − 16）：文件图标 12→44，间距 12，文本列 56 起，动作提示右端距行右边 12。

**动作提示文案**：文件 = 「打开」；目录 = 「进入」（`product.md` §1 分流规则：选中目录时 ↵ 为进入该目录）。

#### 文件图标走系统真实图标（已定）

结果 100% 是文件与目录，因此图标取 **`NSWorkspace` 的系统图标**——与访达里看到的一致，用户不需要再学一套自绘图标。**图标裸放，不加块底**：系统图标本身是彩色有形状的，再叠一层圆角块底就是两层形状打架。

| 项 | 规定 |
|---|---|
| 取图方式 | 优先按**文件类型（UTI）**取，不按路径取 |
| 缓存键 | UTI，不是路径——一次查询返回上千条，类型通常只有十几种，缓存后开销可忽略 |
| 尺寸 | 悬浮条 32×32，完整窗口 16×16；Retina 下取 2x 位图，两个尺寸各缓存一份 |
| 例外 | 用户给单个文件设过自定义图标时只能按路径取。这类文件少，走异步补齐，不在首屏阻塞 |
| 兜底 | 取图失败时回落一个中性文档字形，不留空槽 |

图标补齐须与 `product.md` §1 的分页语义对齐：首屏 20 行可同步取，滚到底增量渲染的行异步补图标，不得阻塞滚动。

### 2.6 索引状态角标（**设计稿缺失，必须补**）

`product.md` §7 要求悬浮条呈现六种引擎状态。设计稿未画，须补。落位已定：**搜索行右端、按钮左侧**（查询区弹性宽，角标贴右，与搜索图标左右呼应；与 §七/实现一致）。

| 状态 | 角标文案 | 强调度 |
|---|---|---|
| building | 建索引中 N | 中性 |

### 2.7 悬浮条状态与文案

#### 结果行

| 状态 | 表现 |
|---|---|
| 默认 | 行底透明，文件名常规色 |
| 选中 | 行底高亮 + 文件名提亮 + 右端出现动作提示，**三项同时生效**；文件图标不随选中变化 |
| 悬停 | 用选中态约 50% 强度的行底；**鼠标移动不得改变键盘选中项** |

#### 列表级状态（对齐 `tech.md` 会话状态机六态）

设计稿画出了其中两态（空词、无匹配项，见「悬浮条 空态」屏 `auuzt`）；其余四态须自行实现，样式沿用同一套 token：

| 状态 | 结果区 | 页脚 |
|---|---|---|
| Idle（空词） | 空态提示：一行主文案 + 一行副文案（12pt，所在目录色） | 结果计数隐藏 |
| Searching | 保留上一轮结果至新结果到达（整体替换，不闪） | 计数沿用上一轮 |
| EngineStarting | 空态提示「启动引擎中」 | 状态角标显示启动进度 |
| Offline | 结果照常渲染，角标标注「离线索引」 | 计数照常 |
| Empty（total=0） | 空态提示「无匹配项」+ 副文案 | 「共 0 项」 |
| Warming | 空态提示「索引构建中」（**非错误样式**） | 状态角标「建索引中」 |

**空态形制**：面板不塌陷，保持搜索行 + 空态区 + 页脚三段结构；空态区高度取结果区最小高（建议 1 行高 56 + 内边距 16 = 72），避免面板高度剧烈跳变。

| 项 | 值 |
|---|---|
| 面板高 | **176** = 64 + 1 + 72 + 1 + 38 |
| 空态区 | 高 72，纵向居中，主副文案间距 4 |

| 副文案 | 12pt，取所在目录色 |

| 页脚 | 空词隐藏结果计数；无匹配项显示「共 0 项」 |

#### 空态文案

| 状态 | 主文案 | 副文案 | 页脚计数 |
|---|---|---|---|
| 空词 | 输入关键词开始搜索 | 可搜文件名，也可搜路径 | 隐藏 |
| 无匹配项 | 无匹配项 | 换个关键词试试 | 共 0 项 |

### 2.8 悬浮条交互

**沿用 `product.md` §1 既有键位，本视觉规格不新增任何键**。设计稿页脚四组键位与下表逐项一致。

| 键 | 行为 |
|---|---|

### 2.9 形象（吉祥物）

一个文件夹形象趴在面板顶边上，压在右上角内侧。它不遮挡搜索图标、查询文字与面板圆角。

**窗口顶部预留 70px 形象条**（画布高 100 − 下缘压过面板 34 + 头顶余量 4）；窗口高 = 面板高 + 70。面板顶边仍距可见区顶 **110**。坐标口径（Task 9）：屏幕坐标 y 向下时窗口顶 = 面板顶 − 70；AppKit 坐标 y 向上时窗口顶 y = 面板顶 y + 70。

| 属性 | 值 |
|---|---|
| 素材 | `蓝色文件夹与放大镜吉祥物-透明.png` |
| 素材原始尺寸 | 901 × 762（已按主体裁切 + 4px 边距） |
| 画布尺寸 | 118 × 100 |
| 水平位置 | 右缘距面板右缘 **60**，且右缘距搜索行按钮左缘 **12** |
| 垂直位置 | 下缘压过面板顶边 **34** |
| 锚点 | 面板**顶边**与**右缘**——面板高度随结果条数变化时形象不动；面板变窄时形象随之左移 |
| 层级 | **面板的兄弟节点**，绘制顺序排在面板之后 |
| 主题 | 深浅两套共用同一张素材，不随主题变化 |

**层级是硬约束**：面板开了 `clip`，形象做成面板的子节点会被裁掉；同时它必须排在面板之后绘制，否则压不住顶边。

**避让也是硬约束**：形象压在搜索行之上，而搜索行右端有「打开完整窗口」按钮（§2.3）与状态角标（§2.6）。形象必须与它们留出空档——初版就是因为形象盖住了按钮，按钮在画布上找都找不到。改动形象位置或搜索行右端元素时，两边的空档要一起复核。

**已知限制（Task 9，待实机验收拍板）**：形象条区域属悬浮条窗口，点击落到窗口而非背后应用；ghost/失焦判定按整窗 frame，暂不区分条带。本任务不改为独立穿透窗口（架构代价大），验收清单列「实机确认是否接受」。

#### 素材要求

| 项 | 要求 |
|---|---|
| 透明通道 | **必须有 alpha**。白底 RGB 的 PNG 放在深色面板上会显示为白方块 |
| 投影 | 素材须自带柔和落地投影。**不要用抠白底代替**——投影是浅灰、同为低饱和，会被一起抠掉 |
| 分辨率 | 长边 ≥ 目标显示尺寸的 2 倍（≥ 236px）；当前素材 901px，富余 |
| 构图 | 按主体裁切，四周留边 ≤ 4px。留白过多会导致定位无法对齐面板顶边 |

#### 动作

设计稿是静态姿态，动作由实现补。**能做哪些动作取决于素材格式**：

| 时机 | 动作 | 单张 PNG（当前） | 分层素材 |
|---|---|---|---|
| 待机 | 呼吸起伏 | 上下 1-2px，周期 2.4s | 同 |
| 输入时 | 探头 | 整体前倾 2-3° | 可加眼睛跟随光标 |
| 出结果 | 眨眼 | 做不到 | 闭 80ms + 睁 80ms |
| 无结果 | 耷拉 | 整体下沉 4px | 加闭眼 |
| 引擎启动中 | 张望 | 左右摆 ±3°，周期 1.6s | 同 |

当前素材是**单张 PNG**，眼睛与嘴巴烤在图里，所以眨眼、转眼这类分部件动作做不到，只能整体变换。需要这些动作时，要设计侧提供分层素材（身体 / 眼睛 / 嘴巴分开）。

**后续可选**：状态切换时姿态硬切（无过渡动画）。规格未要求，先记录；若实机观感生硬再补过渡。

#### 素材与画布的关系

设计稿与素材**放在同一目录**：`docs/specs/floatbar-visual/` 下同时放 `原型.pen` 与 `蓝色文件夹与放大镜吉祥物-透明.png`，图片按同目录相对路径引用。

**文档一移动，图片引用就断。** 这个坑已经踩过一次：设计稿最初在 `~/.pencil/documents/<id>/` 下、素材在仓库里，靠 `../../../project/...` 跨目录引用；把文档存进仓库后，这个相对路径指到了不存在的地方，画布上直接变成「图片找不到」的马赛克格。修法就是把引用改回同目录相对路径。

同理，**改素材文件名必须同步改引用**；换素材时保持同名覆盖最省事。交付给前端时以素材文件本身为准，不以画布为准。

## 六、实现注意（egui/eframe 栈）

### 6.1 毛玻璃：设计稿观感与产品现实的落差

悬浮条设计稿的面板底为 `#191C21CC`（80% 不透明）+ 40px 背景模糊，画在可控的深色壁纸上。**产品中面板下方是用户的任意桌面内容**，两条路：

| 路线 | 做法 | 结论 |
|---|---|---|
| ① 实底（降级备注） | 去掉 alpha，深色 `#191C21`、浅色 `#FFFFFF`；观感与设计稿差一档，但文字对比度不随桌面变化 | 平台毛玻璃不可用时的降级路径（当前未启用） |
| ② 系统毛玻璃 | 面板窗下挂同级垫窗承载 `NSVisualEffectView`（material `UnderWindowBackground`、blendingMode `BehindWindow`、state `Active`），egui 清屏走透明 | **已落地（PoC-7，2026-10-17）**：面板底保留 40% alpha（§4.1）；全屏 Space 已解（垫窗装好 vibrancy 后最后换类 NSPanel + `NonactivatingPanel`）；取证见 `v2-ui/poc-results.md`「PoC-7」 |

**纯 alpha 底不可取**：透明底叠在用户的亮色文档/壁纸上，12pt 的所在目录文字会明显掉对比度。② 已按「磨砂 + 40% alpha 面板底」落地；平台能力不可用时才退 ① 实底。

完整结果窗口的设计稿本就是实底（`#1A1D22` / `#FFFFFF`），不受此项影响。

`product.md` 的非目标清单原把「系统毛玻璃/材质效果」列为 v2.1 候选；本设计在 v2.0 观感迭代中提前落地（PoC-7），v2.1 条目随之失效。

### 6.2 窗口装饰

完整结果窗口是常规 App 窗口（可缩放、可最小化，`product.md` §2）。egui 无边框窗口下，交通灯有两条路：

| 路线 | 做法 |
|---|---|
| 自绘 | egui 画三个圆，自行接关闭 / 最小化 / 缩放 |
| 保留系统 | 窗口不设 `decorations:false`，由 macOS 提供标题栏 |

设计稿画的是自绘形制（12 圆、红黄绿、无标题文字）。走自绘需一并处理三键行为与拖拽移动窗口，**须先确认 eframe 下拖拽与三键的可行实现**；不确定时保留系统装饰，视觉与设计稿不符但行为可靠。

**2026-10-17 定案（已落地）**：保留系统交通灯与系统窗口行为（拖拽 / 关闭 / 最小化 / 缩放 / 双击 zoom）；`titlebar_shown(false)` + `fullsize_content_view(true)` 透明标题栏，内容绘制到标题栏下方；标题不显示，右端齿轮见 `settings-visual.md` §3.1。**不自绘三圆、不自行接管三键**。

悬浮条走 `decorations:false`（无装饰），不受此项影响。

### 6.3 阴影与圆角

- **悬浮条**：无边框 + 自绘圆角/阴影，阴影按 §4.6 映射到 egui 的阴影参数（含扩展值）；圆角按 §4.4。
- **完整窗口**：保留原生窗口，阴影与窗口圆角由系统提供（`with_has_shadow(true)`）；应用仅在内容层按半径 12 补 1px 内描边。§4.6 的窗口阴影数值（偏移/模糊/扩展）**仅作参考**，原生阴影不可逐值控制（2026-10-18 验收登记）。

悬浮条毛玻璃垫窗的圆角走 `NSVisualEffectView.maskImage`（`NSBezierPath` 圆角矩形）；**禁 `layer.masksToBounds`、禁换 `contentView` / 加兄弟层**——会打死 vibrancy（PoC-7 实证，见 `v2-ui/poc-results.md`）。

### 6.4 高度变化

- 悬浮条：结果条数变化会改变面板高度。**2026-10-17 定案（PoC-6 实机对照，见 `v2-ui/poc-results.md`「PoC-6」）**：
  - **加过渡动画，120ms**，实现为**窗内平滑**：窗口先在目标高一侧就位（增长先撑到目标、收缩等动画完成再收），面板高度的动画全部在 egui 窗内绘制；**静止时窗口 = 面板 + 形象条 70**（Task 9；垫窗只覆盖面板，不含形象条；过渡期窗口瞬时大于面板，透明区只在约 0.12–0.2s 内存在）。
  - 顶边钉住重锚沿用：高度变化时顶边坐标不变，向下生长。
  - 每次高度变化只发 **1 次**原生 resize。对照实测：逐帧驱动窗口高 = 134–175 次/次变化，即抖动的来源。
  - 配套 `NSView.layerContentsPlacement = TopLeft`（resize 时旧帧钉左上、裁切而非拉伸）。
- 完整结果窗口：窗口可缩放，**表格区吸收高度变化**，标题栏 / 搜索行 / 表头 / 状态栏高度恒定。

### 6.5 大结果集

`product.md` §1 的语义是首屏 20 行 + 滚到底增量渲染至 K 行（悬浮条）；完整窗口走虚拟化只渲染可见行（`product.md` §2）。视觉侧要求：

- 两形态结果行高固定（悬浮条 56 / 窗口 30），便于虚拟化按固定行高计算
- 滚动条默认隐藏，滚动时出现（设计稿未画，须补样式）
- 图标（若走 §2.4 路线 B）异步补齐，不得阻塞滚动

### 6.6 深浅色

必须在启动时探测系统外观并在变化时重绘（`tech.md` ADR-8：KVO 随换类失效，已自建探测）。两套主题的**结构、尺寸、间距完全一致，只有颜色与阴影不同**——实现上把 §4.1 / §4.2 做成两组语义 token，切主题即换值，视图层不写条件分支。
