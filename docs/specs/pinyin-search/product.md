# 拼音搜索（全拼）产品规格

- 日期：2026-11-15
- 状态：已确认（待实现）
- 关联：设计 `docs/superpowers/specs/2026-11-15-pinyin-search-design.md`；实现计划
  `docs/superpowers/plans/2026-11-15-pinyin-search.md`

## 1. 功能与范围

纯 ASCII 全拼查询词直接命中中文文件名：`shu` → 数/书/树，`shuxue` → 数学，
`shux`（未打完的末音节）→ 数学。

- **默认开启，无开关**：没有配置项可关闭；单次查询可用 `case:` / `whole:` 规避（§2.6）。
- **查询侧展开**：拼音在查询时展开为汉字字符集，索引内容、内存布局、落盘格式零改动；
  旧索引直接可用，无迁移。
- **全客户端自动生效**：实现位于 engine 查询层，CLI 与 GUI 经 daemon 获得同一行为，
  protocol 不变。
- **逐键输入可用**：GUI 60ms 防抖下的连续查询结果稳定，打字过程不闪烁（设计目标 4；
  单字母查询的短暂噪音属已知局限，见 §3 第 4 条）。

非目标：

- **首字母匹配**（`sx` → 数学）：歧义集合过大，查询侧展开不可行。设计边界为其预留
  索引侧方案的位置；届时替换匹配层，行为契约不变。
- 索引侧拼音预存（Spotlight 式读音标注）。
- 混合词（`数xue`）、通配符词（`shu*`）、`whole:` 词的拼音展开。
- 日文假名、韩文等非汉字表音文字的读音匹配。
- 配置开关（默认开启，不提供关闭项）。

## 2. 启用条件与命中语义

### 2.1 启用条件

一个文件名词（`path:` 之外的词）同时满足以下条件才编译拼音分支；任一不满足即维持
纯字面匹配，无提示、无错误：

| # | 条件 | 说明 |
|---|---|---|
| 1 | 整轮非 `case:`、非 `whole:` | `case:` 是精确意图，拼音是模糊召回，不叠加 |
| 2 | 词只含 ASCII 字母与 `'`，且至少一个字母 | 小写折叠后判定；`Shu` 与 `shu` 同。数字、空格、其他符号出现即不展开 |
| 3 | 词能切分为合法音节序列（§2.2） | 否则静默回退纯字面 |
| 4 | 词不是 `path:` 词 | 路径词恒不展开 |

### 2.2 切分

- 音节表：由读音数据派生（ASCII 完整读音约 419 个，含 `hm`/`hng`/`m`/`n` 等叹词音节；
  `ü` 记作 `v`）。派生而非硬编码保证切分表与字符集同源：表里没有的音节必然也匹配不到
  任何字（数量与边界见 `tech.md` §3）。
- **完整音节优先**：枚举全部可行切分（每段为完整音节，末段可为任意音节前缀），
  全部参与命中（OR）。歧义切分是真实需求：`fangan` 同时命中方案（fang+an）与
  反感（fan+gan）；`xian` 同时命中先（xian）与西安（xi+an）。
- `'` 为强制分段边界：边界两侧各自单独切分，边界内仍全枚举。`xi'an` 至少产出
  `[xi][an]`，另有 `[xi][a][n]`（`a`、`n` 都是完整音节）；没有任何方案跨过边界。
- 可行切分超过 8 种时截断取前 8 种（最长优先顺序），防御组合爆炸。
- 无任何可行切分（`pdf`、`shuxq`）→ 不展开。

| 查询词 | 切分 |
|---|---|
| `shu` | `[shu]` |
| `shuxue` | `[shu][xue]`、`[shu][xu][e]` 等 |
| `shux` | `[shu][x]`（末段前缀） |
| `sh` | `[sh]`（末段前缀） |
| `fangan` | `[fang][an]`、`[fan][gan]`、`[fa][n][gan]` 等（上限 8 种） |
| `xi'an` | `[xi][an]`、`[xi][a][n]` 等 |
| `pdf` | 无可行切分 → 不展开 |
| `dot` | 无可行切分（`do` 非完整音节、`dot` 非任何读音前缀）→ 不展开 |

### 2.3 读音与字符集

- 声调剥离；`ü` 归一为 `v`（`lv` → 绿/律，主流 IME 习惯）。
- 多音字任一读音参与：`数`（shǔ/shù）在 `shu` 集；`长`（cháng/zhǎng）同时在 `chang`
  与 `zhang` 集；`行`（xíng/háng）同时在 `xing` 与 `hang` 集。
- 字符集按**读音前缀**建：前缀 `sh` 的集 = 任一读音以 `sh` 开头（sha/shai/shan/shang/
  shao/she/shen/sheng/shi/shou/shu/shua/…）的全部汉字；末段部分音节由此自然支持。
- 字符域：CJK 统一表意文字基本区 U+4E00–U+9FFF。扩展区与兼容区汉字不参与
  （已知局限，§3）。

### 2.4 命中语义

- 拼音命中 = 文件名中存在**连续**汉字序列，逐字归属对应音节的字符集（第 i 字 ∈ 第 i
  段集）。字符集之间不允许插入其他字符：`数-学` 不被 `shuxue` 命中。
- 命中位置任意：`shu` 命中「报告书」。
- 命中选择：一个字面匹配 OR 拼音匹配任一成立即命中；多个切分方案任一成立即命中。
- 拼音分支与字面匹配同数据源（文件名），CJK 字节不受小写折叠影响。
- 全 ASCII 文件名不参与拼音匹配（快速路径，也避免把英文名误判为可拼读）。

### 2.5 评分

沿用现有相关度档位（3 = 名称开头命中，2 = 字面整词边界，1 = 子串）：

- 拼音命中起点在名称首字符 → 档 3。
- 拼音命中起点在名称中部 → 档 1。
- 字面与拼音同时命中取高档位；档 2 只来自字面匹配。

效果：查 `shu` 时「数学.pdf」（拼音开头）排在「季度报告书.docx」（拼音中部）之前。

### 2.6 与现有语法的交互

| 查询 | 拼音展开 |
|---|---|
| `shu` | ✓ |
| `shuxue` | ✓ |
| `shux` | ✓（末段前缀） |
| `xi'an` | ✓（强制边界） |
| `Shu` | ✓（折叠后纯字母） |
| `case:shu` / `case:README` | ✗（整轮） |
| `whole:shu` | ✗ |
| `shu*.pdf` / `*shu` | ✗（含通配符） |
| `path:shu` | ✗ |
| `数xue`（混合词） | ✗（词含非字母） |
| `dot` | ✗（`do` 非完整音节、`dot` 非读音前缀，切分失败） |
| `pdf` | ✗（无可行切分） |

## 3. 已知局限

1. 首字母不支持（`sx` 不命中数学）。设计边界为其预留：将来走索引侧方案时，
   `CPattern` 的拼音分支换成索引序列匹配，行为契约不变。
2. `xian` 同时匹配先与西安（全切分 OR）；`xi'an` 只强制该处边界，边界内仍子切分
   （仍可能按 `[xi][a][n]` 命中三字序列），不保证只命中两字词。
3. 混合词（`数xue`）不展开；`whole:` 与通配符词不展开。
4. 单字母查询（`s`）集合达数千字，结果噪音大；逐键输入时短暂出现，属可接受行为
   （Spotlight 同样如此）。
5. 仅 CJK 基本区汉字；扩展区/兼容区不参与。
6. `ü` 只接受 `v` 写法（`lv` → 绿），不接受 `lü`（与主流 IME 一致）。

## 4. 验收标准

1. `shu` 命中含「数」「书」「树」的文件名（拼音命中，任意位置）。
2. `shuxue` 命中「数学」；`shux` 同样命中（末段未打完）。
3. 查 `shu` 时「数学.pdf」排在「季度报告书.docx」前（拼音前缀档 3 高于中部档 1）。
4. 英文文件名的字面搜索行为不变：`shu` 仍字面命中 `shu.txt`；全 ASCII 名不参与拼音匹配。
5. 索引与落盘无变化：旧索引直接可用，无需重建；`parity` 测试不受影响。
6. `case:` / `whole:` / 通配符 / `path:` / 混合词下拼音不生效（§2.6 表逐条）。
7. 三门禁（fmt / clippy / test）全绿；新增测试经突变验证。
